# Reference deployment — source map and offline staging

This payload comes from the running server. Compare a clean-host deployment with that server, not with an older standalone archive. Source collection was read-only. Private-state backup design, live data import, enrollment, DNS changes, activation, release and installation on the test server are separate operations. For the v0.14.0 system installer, prerequisites and rollback see [Ubuntu installation](ubuntu-install.md). The staging tool below is intentionally offline.

`deployment/source.json` enumerates every candidate payload file, content digest, mode, source classification and deployment link. `ownership.json` records observed principals and modes (not a substitute for effective ACL testing). `platform.json` records the reference versions, package observations, service accounts and enabled vs on-demand units; `dependencies.json` records installed venv distributions and env **key names**, not values. `binaries.json` identifies the external Node, Pi CLI entrypoint and renderer ffmpeg bytes. Reinstall dependencies from their locks; do not copy an old venv or substitute the newest CLI. `docs/licenses/` contains the distribution notices.

## Necessary adaptations (no alternate runtime)

- Hostnames, Telegram identities, links and instance-specific labels inside live scripts, HTML, units and paths are typed `@@NAME@@` bindings. Broker names derive from the actual Telegram venv path as the deployed code does. Peer suffixes used by Telegram links derive from the full numeric peer. No production binding defaults are stored. The destination keeps the original services and paths; staging expresses absolute links as equivalent links inside the offline root.
- Telegram imports the same `config` interface; a small adapter replaces the deployment's credential literals with `/etc/pi-web-instance/telegram-client.json` (`api_id`, `api_hash`, optional `proxy`). The session filename is `account.session`. The original alias resolver reads its name-to-peer dictionary from optional `telegram-aliases.json` in that directory. These inputs must be root-controlled and readable only by the appropriate service group. Missing credentials are not anonymous authorization.
- `pi-nikita.service.d/50-conversation-profiles.conf` obtains the same `PI_WEB_CONVERSATION_TITLE` and `PI_WEB_CONVERSATION_PROFILES` via private `profile-catalog.env`, rather than publishing the enrolled individuals in the unit file. The reference panel and per-peer storage implementation are unchanged.
- Nginx retains the live map logic, reader grant checks, cookie scope and Save proxy. Four reader access values are private inputs; existing publication mappings come from `/etc/pi-web-instance/legacy-articles/*.map`, not public source. No grant rows ship. Socket services still use systemd `LoadCredential` as on the primary.
- The reference card's `/install` URL redirects to GitHub Pages. Pages selects a checksum-pinned release; the offline assembler never fetches it.

## Manual staging (not an installation)

1. Unpack the source archive on a trusted machine under an ordinary user. Run `python3 -B tools/prepare.py`. Use `python3 -B tools/check.py` for a disposable synthetic test; never use its fixture as an enrolled instance. Do not put private input files inside the repository.
2. For a real staged tree provide a private JSON object keyed by `deployment/bindings.json`. Values are strings. Omit fields typed `derived` or `venv-instance`; the assembler calculates them. `*_PEER`, `DEBRI_CHANNEL`, `OWNER_ID`, and `ACCOUNT_ID` are positive magnitudes; the code retains its original sign conventions. `LEGACY_LAB_PEER` is the historical distinct route. `READER_ACCESS` is a URL-safe access token; the three cookie values are independent 64-character random hex strings. Do not reuse production access on a reachable test host. Private credentials and profile stores are **not** generated by this command.
3. Run `python3 -B tools/prepare.py --bindings /private/path/bindings.json --stage /private/path/new-root`. The output directory must not exist. This checks and renders files only. It does not chown, write to `/etc`, register units, install packages, open ports or start clients. Treat the result as private, since it now contains bindings. Linux owner/group mapping and directory ACLs must be applied on the destination, not inherited from the Mac.

## Linux operator gates — before exposing anything

- Use a clean Ubuntu 24.04 x86-64 host or isolated VM; check ports, space, users, the fixed workspace paths, group membership and mounts. Do not extract over a working installation or enable every template unit. Do not copy host SSH keys, production TLS keys or old privilege state.
- Recreate the checked Node 22.23.4 and Pi 1.6.0 layout (`/opt/node22`, `/opt/pi-web-runtime/node_modules/.bin/pi`), npm dependencies from each lock, separate venvs, Playwright browser binaries, offline speech assets and renderer ffmpeg. Build science from its Dockerfile and lock; supply the resulting `/opt/nikita-science/image-id`. Use the dedicated ext4 project mount for CurveLab before placing its worktree. Its Docker build context is `/srv/nikita-projects/curvelab/runner-build`. The reference worker requests four CPUs; the Ubuntu installer caps this setting and its thread counts for smaller destination hosts.
- Recreate empty runtime/work/data directories, the `pi-browser`/`pi-nikita` privilege boundary, the browser-launch rule and required ACLs for the shared profile directory. Verify real UID and file writes off/on/off, `visudo -c`, systemd unit validation, the restart gate, and the role tool matrix. A file manifest cannot validate effective permissions. Do not grant broad sudo/file access just to make a check pass.
- Configure a fresh non-empty panel password, site-entry config, an editor password, allowed hosts and test-host TLS **before** permitting external access. The original browser auth supports an unconfigured local mode; never expose it that way. Validate `nginx -t`, anonymous and authenticated routes, private reader grants, Save routing and scoped cookie behavior. The existing exporter additionally expects the configured instance project roots and data; a bare source tree is not an instance backup.
- Keep `tg-agent`, the recovery login helpers, both Telegram archive timers and external generation inactive until deliberately enrolled with an independent account or an exclusive cutover. Missing private inputs include the browser base prompt, Telegram `assistant-system.txt`, `working-rules.md`, character and role files, any instance `AGENTS.md`, profile catalog/store, settings and grants. Supply these privately rather than substituting a demo personality. Keep real `.session` files on one active host only.
- Before declaring parity: verify actual profile independence, delivered text/voice/circle addressing, role-specific tools, archives and reader authorization, PDF/media, scientific work, Save behavior, and reboot/rerun without resetting state. Distinguish an inactive account/provider from a missing handler. A local panel smoke test is not a Linux deployment test.

**Import evidence (2026-11-27):** the reference inventory supplied 368 regular source/config files and 10 links, rechecked against the host without drift, plus 3 sanitized nginx map definitions and the Telegram credentials interface. Of the 372 payload files, 293 are byte-identical and 79 are adapted or secret-free configuration boundaries. All 29 enumerated application units and their 15 drop-ins are represented; first-party service script entrypoints resolve in the rendered fixture. The source/archive scans found no matches against the enrolled credentials and instance values checked, and Gitleaks 8.24.3 reported no leaks. These checks do not prove the absence of every conceivable private detail or replace review of future diffs.

**Acceptance status:** actual source and live unit definitions imported and audited, offline fixture and authenticated loopback panel exercised. A full manual Linux install, file ACLs under workload, mounted services, reboot, actual Telegram delivery and paid providers remain unverified. No claim of full end-to-end equivalence until those checks pass.
