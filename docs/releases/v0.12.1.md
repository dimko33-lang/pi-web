# v0.12.1 — Bounded DM history and uninterrupted active replies

This patch fixes what the installable Telegram worker sends to the model. It does not change who may speak to Nikita.

- **Dialogue measures messages.** Previously `Dialogue = 1` and `Dialogue = 500` both resumed the entire saved Pi session for that private chat. Now the worker selects up to the saved number of visible messages from same-peer reply exchanges, newest first for selection and oldest first in the request. One question and one answer are two messages. Pausing a saved count, or setting it to zero, sends no automatic history. An explicit same-chat Reply may still quote one target. Old Pi sessions are not replayed. This applied to excess history within one DM, not to sharing sessions between people. The group Person / Group / BG switches keep their independent behavior.
- **A working model can take longer than six minutes.** Thinking, text and tool events keep the turn alive. Only the finished reply is delivered. The default local watchdog waits for 20 minutes of **silence**, not 20 minutes of total runtime. Set `NIKITA_PI_IDLE_SECONDS` on the worker to change this; `0` disables the watchdog. A private timeout identifies the stall. The model provider and individual tools can still impose their own limits.
- **The normal test command works.** `npm ci && npm test` exercises source restore, profile persistence and tool routing without credentials. `npm run test:telegram` adds isolated Telegram and loopback-provider regressions, including the actual payload for owner and guest DMs and all eight group switch combinations. The [setup guide](../usage.md) now correctly describes private access for the owner and explicitly enrolled guests, and the tools available to each.
