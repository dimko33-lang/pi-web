# Ubuntu 24.04: new installation

Use a **fresh** Ubuntu Server 24.04 x86-64 system with systemd, at least two vCPUs, 18 GiB free and inbound TCP 80/443. Take a machine snapshot first. This release is not an in-place upgrade or a project deletion tool. It refuses an installation owned by another release. To roll back, keep new private data separately and restore the machine snapshot; do not install an older kit over this one.

```sh
curl -fsSL https://dimko33-lang.github.io/pi-web/install.sh | sudo bash
```

The launcher's `--verify-only` mode verifies a pinned download without installing. Ubuntu, Node/npm, PyPI, Playwright, speech assets and Docker images require network access. Re-run the **same** release to resume a failed stage. State is private under `/var/lib/pi-web-installer`. The browser and Telegram identities are separate. The new owner link is in `/var/lib/pi-web-installer/access.txt` (root only); browser Pi login runs as `pi-browser`, never as root. Only the owner should have panel access; host administration mode starts off.

By default the IPv4 address is taken from SSH or routing and mapped to a dashed address under `sslip.io`. If necessary pass `PI_WEB_PUBLIC_IP` or set `PI_WEB_DOMAIN` to a base domain you control, with its apex, `www`, `panel`, `pi`, `editor`, `www.editor` and `static` pointing at the server. Put variables in the installer's environment, e.g. on the **right** of the pipe with `sudo env PI_WEB_DOMAIN=lab.example.org bash`. ACME requires working public DNS and port 80. `PI_WEB_TLS=self-signed` explicitly selects private test TLS (trust its certificate separately); there is no silent HTTP fallback.

## Empty workspaces, working tools

No user application runs on startup. The application host (`editor.BASE`) initially returns 404. It is independent of the authenticated owner panel; publishing to it makes the application's HTTP responses public. Applications needing private pages must implement their own authorization. The two static sites (`pi.BASE`, `static.BASE`) also start without content. The archive UIs remain available with empty data. No articles, projects, template project source or previous releases are downloaded in a later install step.

- **Browser:** the owner can create and edit files in the browser agent's own `/srv/pi-workspaces/browser/rootfs/opt/projects`. Browser files and Telegram workspaces stay separate. The panel's authenticated Save includes both.
- **Static hosting:** on an explicit publishing request a bound publishing group can create or edit `site/<name>/index.html` and supporting files through the real workspace tool. The two bind mounts map to `/var/www/pi-web-public` and `/srv/nikita-projects/static/public`. These are private-instance files even if the owner chooses to serve them publicly. Do not put secrets there.
- **App hosting:** the development group has `project_command`; the owner can also use `sudo nikita-project exec` on the host (shell script from stdin). Commands run in `/project` on the bounded mounted volume, inside the existing no-network project container with its scoped dependency proxy. Create the app and its own `package.json`, install its dependencies in this workspace and supply `npm start` listening on `127.0.0.1:5080` or `PORT`. No source or lockfile from a user's project is preloaded. `nikita-project check` verifies a candidate without switching traffic; `publish` health-checks then switches the separate app hostname. `withdraw` takes it offline and `rollback` selects the previous slot, including the initial unpublished state. The same broker accepts `@check`, `@publish`, `@withdraw`, `@rollback` from the authorized development group only. Neither the app nor the development container receives the panel password or Docker socket.
- **Private Save:** the download button invokes the private registry/rsync exporter, not the release packer. `/srv/nikita-projects`, `/var/www`, both application workspaces and the Salon publication/archive stores are recursive backup roots, including private working code, project data and release slots. Place other roots explicitly in `/etc/nikita-home-save/projects.json`; symlinks do not include external targets. Save can contain secrets, private correspondence and project IP. Keep it private and encrypted at rest. Save is not a bootable disk, an encrypted export by itself, or a cross-store transactional snapshot. Before cutover, quiesce writes and test an actual restore; rebuild disposable dependencies from locks. The public package checks are deliberately **not** applied to a private Save.

## Enrollment (optional and separate)

The panel starts with owner DM and default guest DM; group slots are shown when their peer is explicitly supplied. Supply your own root-owned 0600 partial binding JSON via `PI_WEB_BINDINGS` **before first install**. See `deployment/bindings.json`. Peer magnitudes are positive strings. `PROJECT_PEER` is the shared publishing group, `LAB_PEER` the sandbox app group and `ARRI_PEER` the secondary static-site group (historical key, not project content). Unbound identifiers give no actual peer a group capability. Individual DM entries belong to the private `/etc/pi-web-instance/profile-catalog.env`, not Git. Existing saved settings are not migrated or erased by this release.

Keep `tg-agent` and both archive timers off until deliberately enrolled. Use a genuinely independent account or fence and stop the old client and collectors first. Provide `/etc/pi-web-instance/telegram-client.json` with integer `api_id`, string `api_hash` and optional Telethon proxy (root-owned, readable only by the required service UID via ACL). Create `account.session` as `pi-nikita` in `/opt/tg-agent` using its venv and private config; verify `get_me().id` against the bound account and disconnect. Telegram Pi uses its own `tg-agent/home`. Once verified, the root operator can create `/etc/pi-web-instance/telegram-enrolled` and explicitly enable/start `tg-agent.service`; check delivery before enabling the optional `nikita-salon-history.timer` and `nikita-salon-piwep.timer`. Removing the marker is not a stop command. Do not run the same account session on two hosts.

Voice/video/image and model authorizations remain private. Gacrux reads `google-key` and its enrollment marker; Anam is the default circle provider with `anam-key` and your bound avatar. HeyGen needs its own key, portrait and explicit provider selection. Broker paths in `/etc/pi-web-speech/` are named by the hash of the Telegram venv path; never put credentials or portraits in Git. Ordinary maintenance does not require a Telegram post or paid generation.
