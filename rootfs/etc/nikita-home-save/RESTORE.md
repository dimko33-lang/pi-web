# Private instance recovery

This is private application data and configuration, not a bootable disk image. The archive may contain credentials, personal instructions, Telegram sessions, source repositories, drafts, articles and correspondence. Do not upload it to the public package builder. A gzip checksum does not establish successful recovery.

1. Preserve the original archive privately. Extract to a new staging directory on a trusted host. Check RECOVERY.json, PROJECTS.json, file permissions, database integrity, links, mountpoints, credentials and application-specific restore instructions. An online export is not atomic across stores. Stop writers for a final migration.
2. Use a clean supported host. Recreate service principals, groups, ACLs and the bounded application volume **before** copying files from that mount. Restore private workspaces, release slots, project data, snapshots, website roots, archive stores and explicitly registered external paths. Do not replace an active installation. The browser service and Telegram service have distinct homes, privileges and private settings. Reset browser host-administration mode to off; do not trust stale job state.
3. Reinstall OS packages, Node, Pi, browsers and private application dependencies from their own locks. Rebuild the science and generic project containers from their trusted contexts, reset the project nginx include to `return 404;` before reactivating it, and republish only approved content. Docker runtimes, caches, live Unix sockets, TLS private keys and SSH host keys are not a portable project backup.
4. Provision fresh TLS and DNS, review all private credentials (including external providers), check authenticated and anonymous boundaries, then check actual application behavior. Start Telegram only when the previous session has been fenced. Check per-peer state, uploads, Notes, private Save and a reboot before cutover.

The new system's private collector recursively includes `/srv/nikita-projects`, `/var/www`, browser and Telegram workspaces, publication and archive data. An empty project host is normal. A project, git history, previous releases, news content or media added to these roots belongs to this private archive, not to public source. External symlink targets require explicit registration in `/etc/nikita-home-save/projects.json`. Preserve the private registry when adding or restoring projects. Never register the entire filesystem. Encrypt backups at rest and keep recovery keys outside the repository.
