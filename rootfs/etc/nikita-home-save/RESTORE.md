# Private application-server recovery archive

This is application data and configuration, not a bootable disk image. Keep it private: includes the Telegram session, model credentials, project access settings and private chats. SSH host keys, OS passwords and TLS private keys are intentionally NOT included. Never unpack into a running host blindly.

1. Use a clean Ubuntu host matching RECOVERY.json. Verify the gzip and extract into an empty staging directory as root with numeric owners and permissions preserved. Review PROJECTS.json, RECOVERY.json and package-versions.tsv. Use the recorded service UIDs/GIDs (including supplementary memberships) or explicitly remap ownership before installing anything.
2. Install needed OS packages including nginx, certbot, rsync, git, Python/venv, tar, Docker where needed, and the recorded Node version in /opt/node22. Install the distribution's normal nginx/systemd infrastructure first. Do not reinstall every recorded OS package blindly. Restore rootfs paths preserving owners, symlinks, modes and hardlinks. Compare configuration before replacing files. /opt/tg-agent is a symlink, not a second project. Recreate empty runtime directories /var/lib/nikita-home-save (root, 0700) and /var/www/instance-site-acme. Inspect StateDirectory, RuntimeDirectory, ReadWritePaths, bind mounts, drop-ins and working directories in the restored units; recreate required paths and accounts before starting units.
3. Reinstall dependencies from the restored locks. For /opt/pi-web-runtime, the Pi web app and /opt/curvelab-editor use the recorded Node version and npm ci; link/install the Pi CLI exactly as the restored app configuration expects. For tg-agent and nikita-image create venv in the project; for nikita-web create /opt/nikita-web-venv. Install each requirements.lock into its venv. Reinstall the matching browser binaries for nikita-web at the path in its unit. Rebuild the scientific worker image from /opt/nikita-science and its requirements; verify/re-pin the image ID if the build produced a new digest. Do not start two Telegram agents using the same Telegram session.
4. Configure DNS, firewall and HTTP-only ACME challenge routing for the target host. Reissue the TLS lineages named in the restored nginx site configs, including apex, panel and editor; replace the old IP-based test alias or omit that vhost as appropriate. Restore/recreate nginx reload hooks for renewal. Run nginx -t before reload. Verify editor authorization, owner-only salon, access maps and cookie policies. Old domain secrets and article tokens are in the archive, not regenerated by the installer.
5. systemctl daemon-reload; restore the originally enabled services, timers and sockets listed in RECOVERY.json after dependencies are ready. Do not enable every archived unit: some are on-demand helpers. Only switch on Telegram after stopping the old instance. Check journal, web logins, editor save/restore, salon texts and media, Telegram, publication and backup download. A gzip or SQLite check is not an end-to-end restore test.

Browser administration (2026-11-21): `pi-nikita.service` and `pi-nikita-entry.service` now run as `pi-browser` from `/srv/pi-workspaces/browser/`, selected by their `95-browser-*` drop-ins. Telegram remains `pi-nikita` in its original tree. Restore the browser code as root-owned, its data/sessions/home as pi-browser, and its parent as root:pi-browser 0750. Install sudo, bubblewrap and acl. `/usr/local/sbin/pi-web-launch` is root-owned 0755 and `/etc/sudoers.d/pi-browser-launch` is 0440; validate with visudo. Recreate `/var/lib/pi-browser-admin` as root 0700, reset state.json to {"root":false} with 0600 permissions, and discard stale jobs before starting the service. Do not restore an enabled root mode automatically. Follow `/srv/pi-workspaces/browser/ADMIN.md` to reinstate the limited Telegram configuration ACLs (rsync/tar do not preserve them). Restore browser entry credentials from its new tree, not the retired Telegram-owned web tree. The owner link and session remain separate from Telegram credentials.

New projects: place self-contained source, data, service templates, install instructions and lockfiles under /srv/nikita-projects/<project>/; this whole tree is automatically captured. Public site files under /var/www/<site>/ are also captured recursively, including /var/www/pi-web-public/ (the journal and exchange demo). Restore the real host directory, not just the empty mountpoint in the Telegram workspace. Validate @@PUBLIC_HOST@@ and the /pi redirect after reissuing TLS. Symlinks do not include external targets; keep project-owned service templates and recovery instructions with the project. DNS is maintained separately at the provider. For projects or databases elsewhere, register their paths in /etc/nikita-home-save/projects.json and add any needed DB-native backups. Never register other mounted hosts, secret system directories or entire disks. An online export is not a single transactional snapshot across different services. For final migration stop writes and make a fresh export before cutover.

CurveLab group runner: before restoring /srv/nikita-projects/curvelab create a fresh ext4 image at /var/lib/curvelab-sandbox/project.ext4 (at least 3 GiB, format ONLY a fresh image), then start the restored mount unit. Restore files into that mounted filesystem, preserving UID 1000 on work/. Rebuild curvelab-project-runtime:stage from runner-build/. Recreate missing node_modules from the lockfile in the worktree. Docker containers and live Unix sockets are not archived. On a fresh host point /etc/curvelab-route/upstream.conf at the original loopback editor until ready, then enable the project sockets, restore the last release tree/dependencies and republish. Do not route nginx to a missing old release socket.
